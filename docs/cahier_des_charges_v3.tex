\chapter{Contexte et Présentation Générale}

\section{Contexte du Projet}
L’entretien automobile est une composante critique pour la sécurité routière, l'efficience énergétique et la préservation de la valeur patrimoniale d'un véhicule. Cependant, la gestion traditionnelle du suivi technique souffre d'un manque de centralisation persistant :
\begin{itemize}
    \item \textbf{Fragmentation des données :} Factures papier égarées, suivis manuels incomplets ou carnets d'entretien perdus.
    \item \textbf{Complexité technique :} Difficulté pour l'automobiliste moyen à comprendre les fréquences de remplacement des pièces d'usure (filtres, bougies, courroies, fluides).
    \item \textbf{Réactivité au lieu de la proactivité :} Interventions souvent réalisées après l'apparition d'une panne sévère, engendrant des surcoûts majeurs.
\end{itemize}

L'émergence des technologies d'Intelligence Artificielle générative et de modélisation orientée \textit{Jumeau Numérique} (Digital Twin) offre une opportunité technologique majeure pour métamorphoser la maintenance automobile en un système prédictif, structuré et conversationnel.

\section{Présentation d'AutoCare AI}
\textbf{AutoCare AI} se positionne comme une plateforme SaaS (\textit{Software as a Service}) multi-plateforme (Mobile \& Web Admin) dédiée au suivi automobile intelligent. Elle permet de :
\begin{enumerate}
    \item \textbf{Instancier un Jumeau Numérique (Digital Twin) :} Générer automatiquement une représentation virtuelle complète du véhicule comportant sa cartographie mécanique (plus de 15 composants surveillés), son calendrier constructeur et ses spécifications techniques.
    \item \textbf{Assister l'utilisateur par l'IA :} Exploiter la puissance de l'API Google Gemini via un prompt hautement structuré garantissant l'extraction exacte des pièces et préconisations constructeurs.
    \item \textbf{Offrir une console d'administration décisionnelle :} Permettre aux administrateurs de piloter les utilisateurs, le catalogue constructeur (165+ marques, 1200+ modèles) et les files d'attente d'analyse IA.
\end{enumerate}

\begin{infoBox}[Valeur Ajoutée Majeure]
AutoCare AI transforme des données automobiles brutes et éparpillées en un profil structuré et synchrone, réduisant jusqu'à 30\% les pannes évitables grâce à la sensibilisation proactive de l'utilisateur.
\end{infoBox}

\chapter{Utilisateurs, Rôles et Modèle de Sécurité}

\section{Acteurs du Système}
Le système distingue deux catégories d'acteurs principales associées à des permissions fines (\textit{Role-Based Access Control - RBAC}) :

\begin{subsection}{Conducteur / Utilisateur Mobile (ROLE\_USER)}
\begin{itemize}
    \item Inscription, vérification d'email et gestion du profil.
    \item Création et gestion de son garage virtuel (véhicules neufs ou d'occasion).
    \item Consultation du Jumeau Numérique : état des pièces, kilométrage et carnets d'entretien.
    \item Consultation des documents constructeurs générés par l'IA.
\end{itemize}
\end{subsection}

\begin{subsection}{Administrateur Système (ROLE\_ADMIN)}
\begin{itemize}
    \item Gestion des comptes utilisateurs (activation, suspension, réinitialisation).
    \item Supervision du catalogue constructeur (marques, modèles, générations).
    \item Consultation des journaux d'audit (\textit{Audit Logs}) et supervision des jobs IA.
    \item Gestion des sessions actives et révocation à distance.
\end{itemize}
\end{subsection}

\section{Modèle de Sécurité et d'Authentification}
Le sous-système de sécurité est articulé autour de Spring Security et du protocole JWT :

\begin{itemize}
    \item \textbf{Access Token :} Durée de vie courte (15 minutes), signé via HMAC-SHA512.
    \item \textbf{Refresh Token :} Durée de vie longue (7 jours), stocké de manière sécurisée et révocable en base de données.
    \item \textbf{Chiffrement des mots de passe :} Algorithme BCrypt avec facteur de travail (\textit{strength}) de 10.
\end{itemize}

\chapter{Intégration IA \& Concept de Jumeau Numérique}

\section{Moteur d'Intelligence Artificielle Google Gemini}
Le moteur IA repose sur l'intégration directe de l'API REST Google Gemini (via `GeminiClientImpl`). Afin d'éviter toute dérive dans les réponses générées (\textit{hallucinations}), le système utilise un générateur de prompt strict (`GeminiPromptBuilderImpl`) imposant un schéma JSON normé.

\begin{subsection}{Structure du JSON Imposé à l'IA}
Le prompt force l'IA à retourner la structure suivante :
\begin{lstlisting}[language=json,caption={Schéma JSON Imposé à l'API Gemini}]
{
  "transmission": "AUTOMATIC",
  "fuelType": "GASOLINE",
  "specifications": {
    "engine_oil_capacity": "4.8 quarts",
    "recommended_fuel": "Unleaded 87"
  },
  "components": [
    {
      "category": "ENGINE",
      "name": "Engine Timing Chain",
      "standardPartNumber": "OEM-TC-77291",
      "standardSpecifications": "Heavy Duty Steel Link"
    }
  ],
  "intervals": [
    {
      "title": "Engine Oil Change",
      "intervalMileage": 10000,
      "intervalMonths": 12
    }
  ],
  "documents": [
    {
      "title": "Owner's Manual",
      "notes": "Official operator instruction guide"
    }
  ]
}
\end{lstlisting}
\end{subsection}

\section{Système de File d'Attente Asynchrone (Job Queue System)}
Afin de garantir une expérience utilisateur fluide et de respecter le temps de réponse HTTP, la génération du Jumeau Numérique est exécutée en arrière-plan :
\begin{enumerate}
    \item Le client mobile soumet la demande de création de véhicule.
    \item Le backend enregistre un job (`JobEntity`) avec le statut `PENDING` et retourne un ID de suivi (`jobId`).
    \item Le service asynchrone invoque l'API Gemini, valide le JSON via `GeminiResponseValidatorImpl`, puis instancie les entités en base de données.
    \item Le mobile consulte l'état du job via un polling optimisé (React Query) jusqu'au statut `COMPLETED`.
\end{enumerate}

\section{Patrons de Conception (\textit{Design Patterns}) Appliqués}
\begin{itemize}
    \item \textbf{DTO / Mapper Pattern :} Structuration stricte des entrées/sorties via MapStruct pour prévenir le surexposition des entités JPA.
    \item \textbf{Repository Pattern :} Abstraction totale de l'accès aux données grâce à Spring Data JPA.
    \item \textbf{Factory \& Builder Patterns :} Construction dynamique des prompts complexes pour Gemini (`GeminiPromptBuilderImpl`).
    \item \textbf{Global Exception Handler :} Centralisation de la gestion des erreurs HTTP via `@ControllerAdvice` et formats de réponse ProblemDetail (RFC 7807).
\end{itemize}
